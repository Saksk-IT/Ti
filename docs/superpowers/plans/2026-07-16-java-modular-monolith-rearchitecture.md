# Ti Java 模块化单体大型重构目标计划

> **用途：** 本文是一份可直接交给 Codex 持续执行数小时或数天的目标契约。执行者必须先完整阅读仓库根目录 `AGENTS.md`，再按本文阶段顺序持续实施；本文不是一次性“生成代码”提示词，也不是允许大爆炸式重写的授权。重构结果必须作为一个新的、可独立运行的项目，统一放在仓库根目录 `Ti-Java/` 中。

## 1. 总目标

在不丢失现有业务能力、不破坏微信小程序、不损坏现有生产数据兼容性的前提下，在当前仓库中新增一个完全独立的 `Ti-Java/` 项目，将现有 Flask Ti 的能力重新实现为：

- **核心后端：** Java 25 LTS、Spring Boot 4.1.x、Spring MVC、Spring Modulith；
- **后端架构：** 领域驱动的模块化单体，每个模块内部采用轻量六边形分层；
- **Web 前端：** Vue 3、TypeScript、Vite，使用 OpenAPI 生成的类型安全客户端；
- **小程序：** 在 `Ti-Java/miniprogram/` 中保存新项目自己的微信原生 TypeScript 小程序副本，保持 API 与行为兼容；
- **AI/数据任务：** 只有确实依赖 Python 数据生态或需要独立资源隔离的任务才保留 Python Worker；普通 AI HTTP 调用留在 Java 集成层；
- **数据设施：** PostgreSQL 继续作为唯一业务事实源，Redis 只承担缓存、限流、会话辅助和短期协调；
- **异步一致性：** 模块内事务 + 领域事件 + Transactional Outbox/可靠事件发布，不引入分布式事务；
- **部署形态：** 初期仍是少量可部署单元，不引入 Kubernetes、Kafka 或大量微服务；
- **迁移方式：** 新旧项目并行开发和独立运行；旧项目只作为只读契约参考，新项目逐模块达到行为等价，最终通过停写、数据迁移和整体切换替代线上运行，不在旧项目内逐路由混合替换。

最终完成时，`Ti-Java/` 必须能够在不引用旧项目运行代码、目录、容器或进程的情况下独立构建、启动、测试和部署。原 Flask 项目完整保留，不删除、不改写；它是否继续部署由用户另行决定。

## 2. 当前基线与重构动机

执行者必须从当前仓库重新生成精确基线，不得把本文中的描述当作最新代码事实。当前已知特征包括：

- Flask 应用工厂与 Blueprint 模块化注册；
- Web 端以 Jinja 模板和静态 JavaScript 为主；
- 微信原生小程序与 Web 共享后端和数据语义；
- PostgreSQL、Redis、RQ Worker、SSE、备份 Sidecar；
- Session 与 JWT 双认证；
- 题库、练习、考试、学习记录、论坛、聊天、通知、教务、AI、后台等多个业务域；
- SQLAlchemy 模型、原生 SQL、服务层和路由层并存，模块间存在共享模型与共享数据库会话。

本次重构首先解决的是类型安全、模块边界、事务所有权、接口契约和可测试性，而不是单纯追求吞吐量。

## 3. 不可违反的工程护栏

### 3.1 工作区与 Git

- 开始前运行 `git status --short --branch`，记录既有修改、删除和未跟踪文件。
- 所有既有脏工作区内容都视为用户资产；不得覆盖、清理、格式化或提交与本目标无关的文件。
- 除本目标计划文件外，实施代码、测试、资源、文档和部署配置必须全部位于 `Ti-Java/` 下；旧项目目录按只读参考处理。
- 不得为了复用代码而修改旧 `app/`、`templates/`、`static/`、`miniprogram-1/`、根 Compose 或根依赖文件。
- 可以复制经确认需要的业务规则、测试夹具、前端资源和小程序文件到 `Ti-Java/`，但复制后由新项目独立维护，不能通过软链接或运行时相对路径依赖旧目录。
- `Ti-Java/` 不创建嵌套 `.git`；它由当前仓库统一版本控制，但目录结构应支持未来独立拆仓。
- 不得使用 `git reset --hard`、破坏性 `git checkout`、强制推送或批量删除用户文件。
- 按 `AGENTS.md` 要求在 `main` 上工作，不新建分支。
- 每个阶段只有在相应测试通过后才能提交；每次只暂存本阶段相关文件并推送 `main`。
- 提交信息应体现阶段，例如 `docs(refactor): inventory legacy contracts`、`refactor(java): migrate catalog reads`。
- 每次推送前再次检查暂存清单，确保没有带入 `AGENTS.md`、本地输出目录或其他既有改动。

### 3.2 数据与生产环境

- 未获得用户在当前任务中的明确授权时，不连接、不修改、不部署真实生产环境，不切换 DNS，不读取真实密钥。
- 所有迁移演练使用本地数据、测试夹具或经过脱敏的备份副本。
- 禁止通过 ORM 自动建表或自动修改生产结构；Hibernate 必须使用 `ddl-auto=validate` 或等价只校验模式。
- 新旧项目并行验证时使用各自独立的数据库/卷；不得让 Flask 与 Java 同时写同一个数据库实例。
- 最终切换时必须先停止旧项目写入，再迁移/校验数据并启动新项目；每张表、每类写命令始终只有一个运行时所有者。
- 迁移期数据库变更必须向前兼容并优先采用 additive change；删除列、改类型、重命名等破坏性操作只能在旧读写方完全退出并完成恢复演练后执行。
- 不得重置用户密码、重新生成用户 ID、改变业务主键或用空库通过测试冒充数据兼容完成。

### 3.3 API 与客户端兼容

- 在迁移矩阵标记完成前，新项目不得偏离现有路径、HTTP 方法、状态码、响应信封、分页语义、空值语义、鉴权方式和错误码。
- 微信小程序是正式客户端；先把现有 `miniprogram-1/` 复制为 `Ti-Java/miniprogram/` 的受控基线，再只在新项目副本中完成适配和验证。
- 新 API 可以规划 `/api/v1`，但旧客户端路径必须通过兼容路由继续工作，直到对应客户端已迁移并验证。
- 禁止仅根据路由函数名猜测行为；必须通过现有测试、实际请求、模型约束和页面调用共同确认契约。

### 3.4 架构约束

- 不按技术层建立全局 `controller/service/repository/model` 大目录；代码首先按业务领域分包。
- 模块之间不得引用对方的内部实体、Repository 或基础设施实现。
- 跨模块同步调用只能通过公开应用 API；非关键后续动作优先使用领域事件。
- 禁止建立不断膨胀的 `common`、`utils`、`shared service`；共享内核仅允许稳定的 ID、时间、分页、错误信封等基础类型。
- 不因“以后可能扩容”提前拆微服务，不引入 Kafka、服务注册中心、分布式事务或 Kubernetes。
- 默认使用 Spring MVC，不使用 WebFlux 包装阻塞式 JPA。
- Redis 不得成为考试结果、学习记录、任务最终状态等业务事实源。
- 不得为了让流水线变绿而删除、跳过或弱化现有有效测试。

## 4. 目标技术栈

执行开始时先核对官方兼容矩阵并固定精确 patch 版本；不得使用 Snapshot、Milestone 或未经验证的预览版本。

### 4.1 Java 后端

- Eclipse Temurin/OpenJDK 25 LTS；
- Spring Boot 4.1.x；
- Spring Modulith 2.1.x 或与所选 Spring Boot 明确兼容的稳定版本；
- Maven Wrapper，禁止依赖机器全局 Maven 版本；
- Spring MVC、Jakarta Validation、Spring Security；
- Spring Data JPA，复杂查询可使用明确的 JPQL、原生 SQL或经论证的查询工具；
- PostgreSQL 驱动、Redis 客户端；
- Spring Boot Actuator、Micrometer、OpenTelemetry 兼容链路；
- JUnit 5、AssertJ、Mockito、Testcontainers、Spring Modulith Test；
- OpenAPI 3.1，并生成 TypeScript 客户端；
- Flyway 作为新项目数据库迁移工具，但只在“阶段 8：数据库迁移所有权切换”中建立正式 baseline。

### 4.2 Web 前端

- Vue 3、TypeScript strict、Vite；
- Vue Router；
- Pinia 只存放客户端身份/UI 状态，服务端数据采用查询缓存方案或局部请求状态；
- OpenAPI 生成客户端是 API 类型的唯一来源，禁止手写第二套漂移的 DTO；
- Vitest、Vue Test Utils、Playwright；
- 默认先实现功能与视觉行为等价，不在迁移期同时进行大范围视觉重设计。

如基线盘点证实公共题库或论坛具有明确 SEO/服务端渲染要求，执行者应先写 ADR，再决定对这些公开页面采用预渲染或 Nuxt；不得在没有需求证据时把整个 Web 强制改为 SSR。

### 4.3 Python 保留边界

只有下列情况可以保留或新增 Python 服务：

- Pandas/NumPy/文档解析等 Python 专属数据流水线；
- 需要单独 CPU/内存限制的代码执行、模型推理或大型导入导出；
- 无法在 Java 中以同等可靠性和维护成本实现的既有任务。

普通 OpenAI 兼容 API、短信、邮件、对象存储和教务 HTTP 调用不因为名称中带有“AI/任务”就自动拆成 Python 服务。

## 5. 目标仓库结构

旧 Flask 项目保持原样。所有新实现集中在一个顶层 `Ti-Java/` 文件夹，并且能够从该文件夹内完成构建、测试、启动和部署。

```text
Ti/
├── Ti-Java/                      # 全新的独立 Java 版项目
│   ├── AGENTS.md                 # 新项目补充工程规则，不覆盖根规则
│   ├── README.md
│   ├── server/                   # Java 25 / Spring Boot 模块化单体
│   │   ├── pom.xml
│   │   ├── mvnw
│   │   └── src/
│   │       ├── main/java/.../ti/
│   │       └── test/java/.../ti/
│   ├── web/                      # Vue 3 + TypeScript
│   ├── miniprogram/              # 新项目自有的小程序副本
│   ├── services/
│   │   └── ai-worker/            # 仅在 Python 保留条件成立时创建
│   ├── infra/                    # 容器、网关、可观测性配置
│   ├── docs/refactor/            # 盘点、ADR、矩阵、进度与切换手册
│   ├── compose.dev.yml
│   └── compose.prod.yml
├── app/                          # 原 Flask 项目，只读参考，始终保留
├── templates/                    # 原项目，只读参考，始终保留
├── miniprogram-1/                # 原小程序，只读参考，始终保留
└── migrations/                   # 原 Alembic 历史，只读参考，始终保留
```

Spring Boot 首先保持一个 Maven 应用模块，通过 Java package + Spring Modulith 表达业务模块。除非构建时间、独立发布或依赖隔离有测量证据，否则不要过早拆成大量 Maven 子模块。`Ti-Java/` 内不得使用指向旧项目文件的软链接、父目录挂载或运行时读取，确保未来可直接抽取为独立仓库。

## 6. 领域模块边界

执行者必须通过模型、路由、服务和真实调用重新校正下列初始边界，并把最终结果写入 ADR 和数据所有权矩阵。

| 目标模块 | 初始职责 | 可能对应的现有区域 |
| --- | --- | --- |
| `identity` | 用户、角色、登录、微信绑定、会话、令牌、账号安全 | `auth`、`user` |
| `catalog` | 科目、公共题库、题目元数据、题库展示 | `quiz`、`subject`、`plaza` |
| `personalbank` | 个人题库、导入导出、个人题目维护 | `user_bank` |
| `learning` | 练习、答案、错题、收藏、复习、学习记录 | `quiz`、`study` |
| `assessment` | 模拟考试、试卷、作答、评分、考试结果 | `exam` |
| `community` | 论坛、版块、帖子、评论、关注 | `forum`、`follow` |
| `messaging` | 私聊、通知、未读计数、实时事件 | `chat`、`notifications`、SSE |
| `campus` | 教务账号、课表、成绩、查询快照 | `edu_schedule` |
| `coding` | 编程题、提交记录、判题相关能力 | `coding` |
| `intelligence` | AI 对话、题目解析、提示词、模型调用记录 | `ai_chat`、AI explain jobs |
| `operations` | 管理后台、系统配置、弹窗、备份、审计、支付状态 | `admin`、`popups`、`payment`、backup |

模块内部建议结构：

```text
catalog/
├── api/               # HTTP Controller、公开 DTO
├── application/       # 用例、命令、查询、事务编排
├── domain/            # 聚合、值对象、领域规则、领域事件
└── infrastructure/    # JPA、Redis、外部客户端、适配器
```

简单 CRUD 不必为了形式制造空层；但领域规则、事务边界和基础设施访问必须可辨识、可测试。

## 7. 持续执行与进度协议

执行者必须创建并持续维护：

- `Ti-Java/docs/refactor/00-current-state.md`：旧项目架构、依赖、运行方式和基线结果；
- `Ti-Java/docs/refactor/01-target-architecture.md`：新项目模块图、关键决策与 ADR 索引；
- `Ti-Java/docs/refactor/02-route-parity-matrix.csv`：每个 Web/API 路由的迁移状态；
- `Ti-Java/docs/refactor/03-data-ownership.csv`：每张表、缓存 Key、对象存储前缀和任务的所有者；
- `Ti-Java/docs/refactor/04-migration-runbook.md`：新旧项目并行验证、最终切换、回滚和数据验证；
- `Ti-Java/docs/refactor/05-progress.md`：当前阶段、最近绿色提交、已运行测试、失败原因、下一步。

`Ti-Java/docs/refactor/05-progress.md` 是跨夜和跨天恢复工作的唯一进度入口。每次提交前后都要更新，至少包含：

```text
当前阶段：
最近通过的提交：
本轮完成：
验证命令与结果：
尚未迁移的路由/表：
已知风险：
下一项具体动作：
```

遇到错误时：

1. 先保留完整错误和最小复现；
2. 定位属于环境、基线、契约、实现还是测试问题；
3. 同一方向连续失败三次后，不再盲目重复，记录原因并采用安全替代路径；
4. 只在缺少必须的用户密钥、需要真实生产权限、出现不可逆数据决策或产品语义无法从仓库推导时暂停询问；
5. 普通编译错误、依赖冲突、测试失败、端口冲突和本地容器问题不是暂停理由，应继续诊断。

## 13. 阶段 5：异步任务与可靠事件

### 工作项
