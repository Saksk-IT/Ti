# 本地构建 Docker 镜像并上传服务器部署

> 适用于无法在服务器上构建镜像的场景（服务器网络受限、配置较低等）。
> 本地构建 → 导出 tar → 上传服务器 → 加载镜像 → 启动服务。

## 架构概览

```
本地电脑                          服务器
+----------+    scp/rsync    +-------------------------+
| docker   | --------------> | /opt/saksk-ti/          |
| build    |  .tar.gz        | +-- compose.prod.yml    |
| + save   |                 | +-- .env.production     |
+----------+                 | +-- migrations/         |
                             | +-- var/ (运行时数据)    |
                             |                         |
                             | Docker 容器:            |
                             | +-- web (Flask+Gunicorn) |
                             | +-- worker (RQ)         |
                             | +-- postgres (数据库)    |
                             | +-- redis (缓存/队列)    |
                             +-------------------------+
```

---

## 1. 本地构建镜像

在本地项目根目录执行：

```powershell
cd E:\Project\Ti

# 1. 清理旧镜像和构建缓存（防止缓存影响镜像内容）
docker rmi saksk-ti:latest 2>$null; $null
docker builder prune -a -f

# 2. 构建镜像（--no-cache 确保完全重新构建）
docker build --no-cache -t saksk-ti:latest -f docker/Dockerfile .

# 可选：打一个带日期的标签（便于回滚）
docker tag saksk-ti:latest saksk-ti:$(Get-Date -Format "yyyyMMdd")
```

验证镜像：

```bash
docker images | grep saksk-ti
```

期望输出：

```
saksk-ti   latest     abc123def456   10 seconds ago   450MB
saksk-ti   20260225   abc123def456   10 seconds ago   450MB
```

---

## 2. 导出镜像为 tar 文件

```bash
# 导出镜像（约 200-400MB）
docker save saksk-ti:latest -o saksk-ti-latest.tar

# 推荐：压缩以减小传输体积（约压缩 50-70%）
gzip saksk-ti-latest.tar
# 生成 saksk-ti-latest.tar.gz
```

> 压缩后体积通常在 100-200MB，上传速度会快很多。
> Windows 下如果没有 gzip，可用 Git Bash 或 7-Zip 替代（见常见问题）。

---

## 3. 上传到服务器

### 方式 A：使用 scp

```bash
scp saksk-ti-latest.tar.gz user@your-server:/opt/saksk-ti/
```

### 方式 B：使用 rsync（推荐，支持断点续传）

```bash
rsync -avP saksk-ti-latest.tar.gz user@your-server:/opt/saksk-ti/
```

### 方式 C：使用 sftp / FTP 工具

通过 FileZilla、WinSCP 等工具上传到 `/opt/saksk-ti/` 目录。

---

## 4. 服务器加载镜像并启动

SSH 登录服务器后执行：

```bash
cd /opt/saksk-ti

# 如果是压缩过的，先解压
gunzip saksk-ti-latest.tar.gz

# 1. 停止现有容器
docker compose --env-file .env.production -f compose.prod.yml down

# 2. 删除旧镜像（防止缓存影响）
docker rmi saksk-ti:latest 2>/dev/null || true

# 3. 加载新镜像
docker load -i saksk-ti-latest.tar

# 4. 启动服务（无需 --build）
docker compose --env-file .env.production -f compose.prod.yml up -d --force-recreate

# 5. 查看状态
docker compose --env-file .env.production -f compose.prod.yml ps

# 6. 验证服务正常
curl -sS http://127.0.0.1:8000/api/ping

# 7. 清理 tar 文件（可选）
rm saksk-ti-latest.tar
```

验证镜像和容器：

```bash
# 查看镜像
docker images | grep -E "saksk-ti|postgres|redis"

# 期望输出（postgres 和 redis 首次会自动从 Docker Hub 拉取）：
# saksk-ti         latest     e0fc5d6cba83   501MB   U
# postgres         16-alpine  ...            ~240MB  U
# redis            7-alpine   ...            ~60MB   U
```

## 5. 首次部署额外步骤

首次部署时，需要初始化 PostgreSQL 数据库结构。

### 5.1 确保 migrations/ 目录已上传

```bash
# 本地上传 migrations 目录到服务器
rsync -avP migrations/ user@your-server:/opt/saksk-ti/migrations/
```

### 5.2 初始化数据库表结构

```bash
# 进入 web 容器执行 Alembic 迁移
docker compose --env-file .env.production -f compose.prod.yml exec web flask db upgrade

# 验证表已创建
docker compose --env-file .env.production -f compose.prod.yml exec postgres \
  psql -U studyuser -d ti_db -c "\dt"
```

### 5.3 从 SQLite 迁移数据（仅旧系统升级时需要）

如果服务器上有旧的 SQLite 数据库（`var/instance/submissions.db`），需要迁移数据：

```bash
# 1. 将 migrate_data.py 上传到服务器
scp migrate_data.py user@your-server:/opt/saksk-ti/

# 2. 在 web 容器中执行迁移
docker compose --env-file .env.production -f compose.prod.yml exec web python migrate_data.py

# 3. 迁移完成后，备份并删除旧 SQLite 文件
mv var/instance/submissions.db var/instance/submissions.db.bak
```

> 后续更新部署不需要重复此步骤，只需步骤 1-4 即可。

## 6. 服务器配置文件

### compose.prod.yml

服务器上的 `compose.prod.yml` 内容（已包含 PostgreSQL）：

```yaml
# /opt/saksk-ti/compose.prod.yml
# 使用方式: docker compose --env-file .env.production -f compose.prod.yml up -d

services:
  web:
    image: saksk-ti:latest
    restart: unless-stopped
    ports:
      - "127.0.0.1:8000:8000"
    environment:
      FLASK_ENV: production
      DATA_DIR: /data
      SECRET_KEY: ${SECRET_KEY}
      DATABASE_URL: postgresql://${POSTGRES_USER:-studyuser}:${POSTGRES_PASSWORD:-studypass}@postgres:5432/${POSTGRES_DB:-ti_db}
      REDIS_URL: redis://redis:6379/0
      RATELIMIT_STORAGE_URI: redis://redis:6379/0
      RQ_QUEUE_NAME: saksk
      PROXY_FIX_ENABLED: ${PROXY_FIX_ENABLED:-true}
      SESSION_COOKIE_SECURE: ${SESSION_COOKIE_SECURE:-true}
      WECHAT_APPID: ${WECHAT_APPID}
      WECHAT_SECRET: ${WECHAT_SECRET}
      DASHSCOPE_BASE_URL: ${DASHSCOPE_BASE_URL}
      DASHSCOPE_API_KEY: ${DASHSCOPE_API_KEY}
      DB_POOL_SIZE: ${DB_POOL_SIZE:-10}
      DB_MAX_OVERFLOW: ${DB_MAX_OVERFLOW:-20}
      DB_POOL_RECYCLE: ${DB_POOL_RECYCLE:-300}
    volumes:
      - ./var:/data
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_started

  worker:
    image: saksk-ti:latest
    restart: unless-stopped
    command: sh -c "rq worker -u $$REDIS_URL $$RQ_QUEUE_NAME"
    environment:
      FLASK_ENV: production
      DATA_DIR: /data
      SECRET_KEY: ${SECRET_KEY}
      DATABASE_URL: postgresql://${POSTGRES_USER:-studyuser}:${POSTGRES_PASSWORD:-studypass}@postgres:5432/${POSTGRES_DB:-ti_db}
      REDIS_URL: redis://redis:6379/0
      RQ_QUEUE_NAME: saksk
      WECHAT_APPID: ${WECHAT_APPID}
      WECHAT_SECRET: ${WECHAT_SECRET}
      DASHSCOPE_BASE_URL: ${DASHSCOPE_BASE_URL}
      DASHSCOPE_API_KEY: ${DASHSCOPE_API_KEY}
    volumes:
      - ./var:/data
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_started

  postgres:
    image: postgres:16-alpine
    restart: unless-stopped
    environment:
      POSTGRES_USER: ${POSTGRES_USER:-studyuser}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-studypass}
      POSTGRES_DB: ${POSTGRES_DB:-ti_db}
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER:-studyuser} -d ${POSTGRES_DB:-ti_db}"]
      interval: 5s
      timeout: 5s
      retries: 5

  redis:
    image: redis:7-alpine
    restart: unless-stopped
    command: ["redis-server", "--appendonly", "yes"]
    volumes:
      - redis_data:/data

volumes:
  postgres_data:
  redis_data:
```

### .env.production

```bash
# /opt/saksk-ti/.env.production

# Flask
SECRET_KEY=your-secret-key-here

# PostgreSQL
POSTGRES_USER=studyuser
POSTGRES_PASSWORD=your-strong-password-here
POSTGRES_DB=ti_db

# 连接池（可选，有默认值）
# DB_POOL_SIZE=10
# DB_MAX_OVERFLOW=20
# DB_POOL_RECYCLE=300

# 微信小程序
WECHAT_APPID=your-appid
WECHAT_SECRET=your-secret

# AI 服务（可选）
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
DASHSCOPE_API_KEY=your-api-key

# 反向代理
PROXY_FIX_ENABLED=true
SESSION_COOKIE_SECURE=true
```

## 7. 日常更新部署流程

代码更新后，只需重复步骤 1-4：

```powershell
# === 本地 ===
# 1. 构建新镜像
docker build --no-cache -t saksk-ti:latest -f docker/Dockerfile .

# 2. 导出并压缩
docker save saksk-ti:latest -o saksk-ti-latest.tar
gzip -f saksk-ti-latest.tar

# 3. 上传到服务器
rsync -avP saksk-ti-latest.tar.gz user@your-server:/opt/saksk-ti/
```

```bash
# === 服务器 ===
cd /opt/saksk-ti
gunzip saksk-ti-latest.tar.gz
docker compose --env-file .env.production -f compose.prod.yml down
docker rmi saksk-ti:latest 2>/dev/null || true
docker load -i saksk-ti-latest.tar
docker compose --env-file .env.production -f compose.prod.yml up -d --force-recreate
rm saksk-ti-latest.tar
```

如果本次更新包含数据库结构变更（新增了 migration），还需要：

```bash
# 上传最新的 migrations 目录
rsync -avP migrations/ user@your-server:/opt/saksk-ti/migrations/

# 执行迁移
docker compose --env-file .env.production -f compose.prod.yml exec web flask db upgrade
```

```bash
# 查看镜像使用状态（U 标记表示正在使用）
docker images

# 删除指定旧镜像
docker rmi saksk-ti:20260101

# 清理所有悬空镜像

# 更彻底的清理（包括未使用的镜像，谨慎使用）

# 查看磁盘占用
docker system df
```

## 9. 数据库备份与恢复

### 备份

```bash
# 备份 PostgreSQL 数据库
docker compose --env-file .env.production -f compose.prod.yml exec postgres \
  pg_dump -U studyuser ti_db > backup_$(date +%Y%m%d).sql

# 压缩备份
gzip backup_$(date +%Y%m%d).sql
```

### 恢复

```bash
# 恢复数据库（会覆盖现有数据）
gunzip backup_20260225.sql.gz
docker compose --env-file .env.production -f compose.prod.yml exec -T postgres \
  psql -U studyuser -d ti_db < backup_20260225.sql
```

### 查看数据库

```bash
# 进入 psql 交互终端
docker compose --env-file .env.production -f compose.prod.yml exec postgres \
  psql -U studyuser -d ti_db

# 常用命令：
# \dt          -- 列出所有表
# \d users     -- 查看 users 表结构
# SELECT count(*) FROM users;  -- 查询数据
# \q           -- 退出
```

## 10. 服务器最小文件清单

使用本地构建方式后，服务器只需保留以下文件：

```
/opt/saksk-ti/
├── compose.prod.yml         # 生产配置（使用 image 而非 build）
├── .env.production          # 环境变量（密钥、PostgreSQL 配置）
├── migrations/              # Alembic 迁移脚本（数据库结构变更时需更新）
└── var/                     # 运行时数据
    ├── uploads/
    └── logs/
```

> 不需要 `app/`、`static/`、`requirements.txt`、`docker/Dockerfile` 等源码文件。
> 数据库数据存储在 Docker volume `postgres_data` 中，不在 `var/` 目录下。

## 11. 常见问题

### 11.1 docker save 报错：No such image

确保镜像名称和标签正确：

```bash
docker images | grep saksk-ti
docker save saksk-ti:latest -o saksk-ti-latest.tar
```

### 11.2 docker load 报错：invalid tar header

tar 文件可能损坏，重新导出并上传：

```bash
# 本地重新导出
docker save saksk-ti:latest -o saksk-ti-latest.tar
gzip -f saksk-ti-latest.tar

# 使用 rsync 上传（支持校验）
rsync -avP --checksum saksk-ti-latest.tar.gz user@server:/opt/saksk-ti/
```

### 11.3 服务启动后仍使用旧镜像

Docker Compose 可能缓存了旧容器，强制重建：

```bash
docker compose --env-file .env.production -f compose.prod.yml up -d --force-recreate
```

### 11.4 PostgreSQL 连接失败

```bash
# 检查 postgres 容器是否正常运行
docker compose --env-file .env.production -f compose.prod.yml ps postgres

# 查看 postgres 日志
docker compose --env-file .env.production -f compose.prod.yml logs postgres

# 检查 .env.production 中的密码是否包含特殊字符（需要 URL 编码）
# 例如 password@123 需要写成 password%40123
```

### 11.5 磁盘空间不足

```bash
docker system df          # 查看 Docker 占用
docker system prune -a    # 清理未使用的资源
docker builder prune -a   # 清理构建缓存
```

### 11.6 Windows 下 gzip 命令不存在

方式 A：使用 Git Bash（自带 gzip）

方式 B：使用 PowerShell 原生压缩

```powershell
docker save saksk-ti:latest -o saksk-ti-latest.tar
Compress-Archive -Path saksk-ti-latest.tar -DestinationPath saksk-ti-latest.zip
```

服务器解压：

```bash
unzip saksk-ti-latest.zip
docker load -i saksk-ti-latest.tar
```

### 11.7 首次拉取 postgres/redis 镜像超时

首次启动时 Docker 需要从 Hub 拉取 postgres 和 redis 镜像，如果服务器网络慢：

```bash
# 方式 A：服务器手动拉取（可重试）
docker pull postgres:16-alpine
docker pull redis:7-alpine

# 方式 B：本地导出后上传（同应用镜像的方式）
docker save postgres:16-alpine redis:7-alpine -o base-images.tar
gzip base-images.tar
rsync -avP base-images.tar.gz user@server:/opt/saksk-ti/
# 服务器加载
gunzip base-images.tar.gz && docker load -i base-images.tar
```

## 12. 上传本地开发数据库到服务器

如果需要将本地开发环境的 PostgreSQL 数据同步到服务器（例如首次部署时携带测试数据）。

### 12.1 本地导出数据库

```powershell
cd E:\Project\Ti

# 导出整个数据库为 SQL 文件
docker compose -f compose.dev.yml exec postgres pg_dump -U studyuser ti_db > db_export.sql
```

> 导出的是纯 SQL 文本，不绑定用户名或数据库名，可以导入到任意 PostgreSQL 实例。

### 12.2 上传到服务器

```bash
rsync -avP db_export.sql user@your-server:/opt/saksk-ti/
```

### 12.3 服务器导入

```bash
cd /opt/saksk-ti

# 确保 postgres 容器在运行
docker compose --env-file .env.production -f compose.prod.yml up -d postgres

# 清空目标数据库（避免主键/表冲突）
docker compose --env-file .env.production -f compose.prod.yml exec -T postgres   psql -U studyuser -d ti_db -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"

# 导入数据
docker compose --env-file .env.production -f compose.prod.yml exec -T postgres   psql -U studyuser -d ti_db < db_export.sql

# 启动全部服务
docker compose --env-file .env.production -f compose.prod.yml up -d

# 验证数据
docker compose --env-file .env.production -f compose.prod.yml exec postgres   psql -U studyuser -d ti_db -c "SELECT count(*) FROM users;"
```

### 12.4 注意事项

- 导入会**覆盖**服务器上的现有数据，操作前建议先备份（见第 9 节）
- 如果服务器的 `POSTGRES_USER` / `POSTGRES_DB` 与本地不同，导入命令中使用服务器的用户名和库名即可
- 导入完成后可删除 SQL 文件：`rm db_export.sql`
