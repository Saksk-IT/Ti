# 本地构建 Docker 镜像并上传服务器部署

```

# 启动开发环境
docker compose -f compose.dev.yml up

# 后台运行
docker compose -f compose.dev.yml up -d

# 查看日志
docker compose -f compose.yml -f compose.dev.yml logs -f web

# 停止
docker compose -f compose.dev.yml down

```

## 1. 本地构建镜像

在本地项目根目录执行：

```powershell
cd C:\path\to\Saksk_1_Ti

# 1. 清理旧镜像和构建缓存（防止缓存影响镜像内容）
docker rmi saksk-ti:latest 2>$null; $null
docker builder prune -a -f

# 2. 构建镜像并打标签（--no-cache 确保完全重新构建）
docker build --no-cache -t saksk-ti:latest -f docker/Dockerfile .

# 可选：同时打一个带日期的标签（便于回滚）
docker tag saksk-ti:latest saksk-ti:$(Get-Date -Format "yyyyMMdd")
```

验证镜像已构建：

```bash
docker images | grep saksk-ti
```

期望输出类似：

```
saksk-ti   latest     abc123def456   10 seconds ago   450MB
saksk-ti   20260201   abc123def456   10 seconds ago   450MB
```

---

## 2. 导出镜像为 tar 文件

```bash
# 导出镜像（约 200-400MB，取决于依赖）
docker save saksk-ti:latest -o saksk-ti-latest.tar

# 推荐：压缩以减小传输体积（约能压缩 50-70%）
gzip saksk-ti-latest.tar
# 生成 saksk-ti-latest.tar.gz
```

> 压缩后体积通常在 100-200MB，上传速度会快很多。

---

## 3. 上传到服务器

### 方式 A：使用 scp

```bash
scp saksk-ti-latest.tar.gz user@your-server:/opt/saksk-ti/
```

### 方式 B：使用 rsync（推荐，支持断点续传）

```bash
rsync -avP saksk-ti-latest.tar.gz user@your-server:/opt/saksk-ti/
```

### 方式 C：使用 sftp / FTP 工具

通过 FileZilla、WinSCP 等工具上传到 `/opt/saksk-ti/` 目录。

---

## 4. 服务器加载镜像

SSH 登录服务器后执行：

```bash
cd /opt/saksk-ti

# 如果是压缩过的，先解压
gunzip saksk-ti-latest.tar.gz

# 1. 停止现有容器
docker compose --env-file .env.production -f compose.prod.yml down

# 2. 删除旧镜像（防止缓存影响）
docker rmi saksk-ti:latest 2>/dev/null || true

# 3. 加载新镜像
docker load -i saksk-ti-latest.tar

# 注意：不再需要 --build 参数
docker compose --env-file .env.production -f compose.prod.yml up -d --force-recreate

# 查看状态
docker compose --env-file .env.production -f compose.prod.yml ps

# 验证服务正常
curl -sS http://127.0.0.1:8000/api/ping

# 验证镜像已加载
docker images | grep saksk-ti

# 清理 tar 文件（可选，节省磁盘空间）
rm saksk-ti-latest.tar
```

### 9.3 清理旧镜像

#### 查看镜像使用状态

```bash
docker images
```

输出示例：

```
IMAGE                    ID             DISK USAGE   CONTENT SIZE   EXTRA
saksk-ti-web:latest      17cdbf86f9e7        501MB          113MB
saksk-ti-worker:latest   3bb6df9846fd        501MB          113MB
saksk-ti:latest          e0fc5d6cba83        501MB          113MB    U
redis:7-alpine           66f2428ae138       61.2MB         17.7MB    U
```

> `U` 标记表示镜像正在被容器使用，**没有 `U` 标记的镜像可以安全删除**。

#### 删除指定旧镜像

```bash
# 删除旧的 web/worker 镜像（从服务器构建时代遗留的）
docker rmi saksk-ti-web:latest saksk-ti-worker:latest

# 删除指定备份版本
docker rmi saksk-ti:backup-20260101
```

#### 验证清理结果

```bash
docker images | grep saksk
```

期望只剩下正在使用的镜像：

```
saksk-ti:latest   e0fc5d6cba83   501MB   113MB   U
```

#### 清理其他无用资源

```bash
# 清理所有悬空镜像（无标签的 <none> 镜像）
docker image prune -f

# 清理所有未使用的镜像、容器、网络（会删除所有没有 U 标记的镜像）
docker system prune -f

# 更彻底的清理（包括未使用的镜像，谨慎使用）
docker system prune -a -f

# 清理构建缓存
docker builder prune -a -f

# 查看清理后的磁盘占用
docker system df
```

#### 定期清理建议

每次部署新版本后，建议执行：

```bash
# 删除旧版本镜像 + 清理悬空资源
docker image prune -f
docker system df
```

## 5. 修改 compose 配置使用本地镜像

修改 `/opt/saksk-ti/compose.prod.yml`，将 `build` 替换为 `image`：

```yaml
# /opt/saksk-ti/compose.prod.yml
# 使用方式: docker compose --env-file .env.production -f compose.prod.yml up -d

services:
  web:
    image: saksk-ti:latest
    restart: unless-stopped
    ports:
      - "127.0.0.1:8000:8000"
    environment:
      FLASK_ENV: production
      DATA_DIR: /data
      SECRET_KEY: ${SECRET_KEY}
      REDIS_URL: redis://redis:6379/0
      RATELIMIT_STORAGE_URI: redis://redis:6379/0
      RQ_QUEUE_NAME: saksk
      PROXY_FIX_ENABLED: ${PROXY_FIX_ENABLED:-true}
      SESSION_COOKIE_SECURE: ${SESSION_COOKIE_SECURE:-true}
      WECHAT_APPID: ${WECHAT_APPID}
      WECHAT_SECRET: ${WECHAT_SECRET}
      DASHSCOPE_BASE_URL: ${DASHSCOPE_BASE_URL}
      DASHSCOPE_API_KEY: ${DASHSCOPE_API_KEY}
    volumes:
      - ./var:/data
    depends_on:
      - redis

  worker:
    image: saksk-ti:latest
    restart: unless-stopped
    command: sh -c "rq worker -u $$REDIS_URL $$RQ_QUEUE_NAME"
    environment:
      FLASK_ENV: production
      DATA_DIR: /data
      SECRET_KEY: ${SECRET_KEY}
      REDIS_URL: redis://redis:6379/0
      RQ_QUEUE_NAME: saksk
      WECHAT_APPID: ${WECHAT_APPID}
      WECHAT_SECRET: ${WECHAT_SECRET}
      DASHSCOPE_BASE_URL: ${DASHSCOPE_BASE_URL}
      DASHSCOPE_API_KEY: ${DASHSCOPE_API_KEY}
    volumes:
      - ./var:/data
    depends_on:
      - redis

  redis:
    image: redis:7-alpine
    restart: unless-stopped
    command: ["redis-server", "--appendonly", "yes"]
    volumes:
      - redis_data:/data

volumes:
  redis_data:
```

## 10. 常见问题

### 10.1 `docker save` 报错：No such image

确保镜像名称和标签正确：

```bash
docker images | grep saksk-ti
docker save saksk-ti:latest -o saksk-ti-latest.tar
```

### 10.2 `docker load` 报错：archive/tar: invalid tar header

tar 文件可能损坏，重新导出并上传：

```bash
# 本地重新导出
docker save saksk-ti:latest -o saksk-ti-latest.tar
gzip -f saksk-ti-latest.tar

# 使用 rsync 上传（支持校验）
rsync -avP --checksum saksk-ti-latest.tar.gz user@server:/opt/saksk-ti/
```

### 10.3 服务启动后仍使用旧镜像

Docker Compose 可能缓存了旧容器，强制重建：

```bash
docker compose --env-file .env.production -f compose.prod.yml up -d --force-recreate
```

### 10.4 磁盘空间不足

```bash
# 查看 Docker 占用
docker system df

# 清理未使用的镜像、容器、网络
docker system prune -a

# 清理构建缓存
docker builder prune -a
```

### 10.5 Windows 下 gzip 命令不存在

方式 A：使用 Git Bash（自带 gzip）

方式 B：使用 PowerShell 原生压缩

```powershell
docker save saksk-ti:latest -o saksk-ti-latest.tar
Compress-Archive -Path saksk-ti-latest.tar -DestinationPath saksk-ti-latest.zip
```

服务器解压：

```bash
unzip saksk-ti-latest.zip
docker load -i saksk-ti-latest.tar
```

方式 C：安装 7-Zip 并添加到 PATH

```powershell
7z a saksk-ti-latest.tar.gz saksk-ti-latest.tar
```

## 11. 与原教程的主要区别

| 对比项 | 原教程（服务器构建） | 本教程（本地构建上传） |
|--------|---------------------|----------------------|
| 镜像构建位置 | 服务器 | 本地 |
| compose.prod.yml | 使用 `build` | 使用 `image: saksk-ti:latest` |
| 启动命令 | `up -d --build` | `up -d`（无需 --build） |
| 服务器需要源码 | 需要完整源码 | 只需 compose 配置文件 |
| 网络依赖 | 服务器需能访问 pip/Docker Hub | 仅本地需要 |
| 部署速度 | 首次较慢（需下载依赖） | 首次较慢（需上传镜像），后续快 |

## 12. 服务器最小文件清单

使用本地构建方式后，服务器只需保留以下文件：

```
/opt/saksk-ti/
├── compose.prod.yml         # 生产配置（独立完整版，使用 image 而非 build）
├── .env.production          # 环境变量（密钥）
└── var/                     # 运行时数据
    ├── instance/
    │   └── submissions.db
    ├── uploads/
    └── logs/
```

> 不再需要 `compose.yml`、`app/`、`static/`、`requirements.txt`、`docker/Dockerfile` 等源码文件。
