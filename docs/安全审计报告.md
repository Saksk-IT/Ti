## CRITICAL 严重漏洞

### C-01: 密钥泄露到 Git 历史 `未修复`

**位置**: `.env`
**问题**: 以下敏感凭证已被提交到 Git 历史（commit cd76d88, 6316ea4）：

- `WECHAT_SECRET=714b6315c5e27cb2689c3c1d5bd54e2d`
- `DASHSCOPE_API_KEY=sk-9305b010e9be495b8407611f14394fd5`
- `SECRET_KEY=Saksk1234567890`

**影响**: 任何有仓库访问权限的人可获取所有密钥，伪造 JWT、调用第三方 API。
**修复**:
1. **立即轮换**所有暴露的密钥（微信 Secret、DashScope Key）
2. 使用 `git filter-branch` 或 BFG Repo-Cleaner 从历史中清除
3. 生成强 SECRET_KEY: `python -c "import secrets; print(secrets.token_urlsafe(32))"`

## HIGH 高优先级漏洞

### H-01: XSS - 模板中使用 `|safe` 过滤器 `已修复 ✅`

**位置**: 所有 Jinja2 模板
**原问题**: 多处使用 `|safe` 过滤器将数据注入 JavaScript，绕过自动转义。
**修复内容**:
1. 所有模板中的 `|safe` 已替换为 `|tojson`
2. 后端已移除 `json.dumps()` 预序列化，改为传递原生 Python 对象，由 `|tojson` 统一处理
**复审验证**: 扫描所有 `.html` 模板文件，`|safe` 匹配数为 **零**。

---

### H-02: DOM-based XSS - innerHTML 滥用 `已修复 ✅`

**位置**: `static/js/bank_data.js`
**原问题**: 部分 JS 文件使用 `innerHTML` 设置包含用户数据的 HTML，未经转义。
**修复内容**: `bank_data.js` 添加了 `escapeHtml()` 函数，所有动态内容插入均已转义。
**复审验证**:
- `bank_data.js`: 第 8-12 行定义 `escapeHtml()`，第 622、648、649 行等均已使用
- `notifications_v4.js`: 已有 `esc()` 函数（第 19-23 行），所有动态数据已转义
- `user_bank_data_v2.js`: 已有 `escapeHtml()`（第 62-69 行），所有表格/建议渲染已转义
- `public_bank_plaza_v2.js`: 已有 `escapeHtml()`（第 4-11 行），所有动态内容已转义
- `exam_builder_inline_v3.js`: 使用 `createElement()` + `textContent`（最安全模式），无风险
