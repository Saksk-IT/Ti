### C-02: 代码执行器无沙箱隔离 (RCE)

- **位置**: `app/modules/coding/services/code_executor.py` 第 130 行
- **OWASP**: A03 - 注入

```python
process = subprocess.Popen(
    [python_cmd, code_file],
    stdin=subprocess.PIPE,
    stdout=subprocess.PIPE,
    stderr=subprocess.PIPE,
    text=True,
)
```

用户代码通过 `subprocess.Popen` 直接在宿主机执行。`code_validator.py` 的黑名单过滤可通过 `__subclasses__()` 等元编程手段绕过，例如：

```python
().__class__.__bases__[0].__subclasses__()  # 遍历所有类，找到可执行系统命令的类
```

**修复建议**: 生产环境必须使用 Docker 容器执行用户代码，配合 `--network=none`、`--read-only`、`--memory` 限制。

### C-03: 存储型 XSS -- 模板 `|safe` 过滤器

- **位置**:
  - `app/modules/main/templates/main/search/search.html` 第 674、704、710 行
  - `app/modules/user_bank/templates/user_bank/bank/bank_search.html` 第 435、468、474 行
- **OWASP**: A03 - 注入 (XSS)

```html
{{ q.content|replace('\n', '<br>')|safe }}
{{ q.full_answer|replace('\n', '<br>')|safe }}
{{ q.explanation|replace('\n', '<br>')|safe }}
```

题目内容由用户通过 JSON/Excel/Word 导入控制，使用 `|safe` 禁用了 Jinja2 自动转义，构成完整的存储型 XSS 攻击链。

**修复建议**: 注册自定义 `nl2br` 过滤器替代 `|replace|safe`：

```python
from markupsafe import Markup, escape

def nl2br(value):
    return Markup(escape(value).replace('\n', Markup('<br>')))

app.jinja_env.filters['nl2br'] = nl2br
```

模板改为：`{{ q.content|nl2br }}`

## 高 (HIGH) -- 6 项

### H-01: Admin 路由缺失认证装饰器 + JWT 绕过全局检查

- **位置**:
  - `app/modules/admin/routes/api_legacy.py` 全部路由
  - `app/modules/admin/routes/api_components/` 全部 11 个组件文件（`chat.py`、`coding_questions.py`、`mail_settings.py`、`notifications.py`、`popups.py`、`questions.py`、`questions_io.py`、`subject_permissions.py`、`subjects.py`、`system_config.py`、`users.py`）
  - `app/__init__.py` 第 314 行
- **OWASP**: A01 - 访问控制失效

Admin 蓝图的 50+ 个端点（含用户管理、权限切换、密码重置）均无 `@admin_required` 装饰器。仅 `users.py` 一个文件就包含 12+ 个敏感路由（`toggle_admin`、`toggle_subject_admin`、`toggle_notification_admin`、`permissions/batch`、`delete`、`create`、`reset_password`、`toggle_lock`、`force_logout`、`export` 等）。全局 `before_request` 钩子在检测到 JWT header 时跳过 admin 权限检查：

```python
# __init__.py 第 314 行
if session.get('user_id') and not has_jwt_token:
    # admin 权限检查在此块内，JWT 请求直接跳过
```

攻击者可构造 `Authorization: Bearer xxx` 头绕过全局 admin 权限检查。

**修复建议**: 为 admin 蓝图添加独立的 `before_request` 钩子，无论 session 还是 JWT 都验证 admin 权限。

### H-02: SECRET_KEY 弱默认值

- **位置**: `app/core/config.py` 第 25 行

### H-03: CORS 允许所有来源

- **位置**: `app/core/extensions.py` 第 20-27 行
- **OWASP**: A05 - 安全配置错误

```python
"origins": ["https://servicewechat.com", "*"]
```

`origins` 包含通配符 `"*"`，任何网站都可向 `/api/*` 发起跨域请求。

**修复建议**: 生产环境移除 `"*"`，通过环境变量配置允许的域名列表。

### H-04: 完全缺失 CSRF 保护

- **位置**: 整个项目
- **OWASP**: A01 - 访问控制失效

项目未使用任何 CSRF 防护机制。所有基于 session 的 POST/PUT/DELETE 端点均可被跨站请求伪造攻击利用。

**缓解因素**: `SESSION_COOKIE_SAMESITE = 'Lax'`（生产配置）可防止大部分跨站 POST。

**修复建议**: 集成 Flask-WTF `CSRFProtect`；API 端点（JWT 认证）可豁免。

### H-06: 文件下载路径遍历风险

- **位置**:
  - `app/modules/user/routes/api.py` 第 775 行
  - `app/modules/main/routes/pages_components/misc.py` 第 17 行
- **OWASP**: A01 - 访问控制失效

```python
@user_api_bp.route('/uploads/<path:filename>')
def uploaded_file(filename):
    return send_from_directory(upload_folder, filename)
```

`<path:filename>` 允许包含 `/` 的路径，未经 `secure_filename()` 处理。

**缓解因素**: 现代 Werkzeug 的 `send_from_directory` 会阻止 `..` 遍历。

**修复建议**: 显式验证 `filename` 不含 `..`，或使用 `safe_join`。

### M-01: PRAGMA table_info 使用 f-string 插入表名

- **位置**: `app/core/utils/database.py` 第 50 行 等约 12 处
- **OWASP**: A03 - 注入

```python
c.execute(f"PRAGMA table_info({name})")
```

虽然当前调用方均传入硬编码表名，但函数接口接受任意字符串，未来维护中可能引入风险。

**缓解因素** *(复审补充)*: `database.py` 已实现 `_q()` 标识符引用函数（`'"' + str(ident).replace('"', '""') + '"'`），部分 PRAGMA 调用已使用该函数，但未全面覆盖。

**修复建议**: 对表名参数添加白名单校验，或统一使用 `_q()` 函数。

### M-06: Redis 无密码保护

- **位置**:
  - `compose.prod.yml` 第 47-51 行
  - `compose.dev.yml` Redis 服务 *(复审补充)*
- **OWASP**: A05 - 安全配置错误

```yaml
redis:
    image: redis:7-alpine
```

开发和生产环境 Redis 均未设置 `--requirepass`，且 `REDIS_URL` 均为 `redis://redis:6379/0`（无密码）。
